# Parlance — 2026 recap (Rive)

A ten-scene, data-bound Wrapped-style recap for the fictional language-practice app **Parlance**, authored as RML for the Rive CLI (1.6.0). Pure RML: there are **no Luau scripts**, so the unsigned `.riv` from `--once` has nothing that needs signing.

## Preview

```bash
cd apps/parlance/rive
rive .                                   # live previewer (window at 390x844)
python3 tools/fixture.py fixtures/extreme.json         # previewer with a fixture applied (--data)
python3 tools/fixture.py fixtures/zero-user.json --screenshot=out.png --advance=150
tools/shot.sh 9 out.png --data=personaIndex=3          # headless: navigate to scene 9 and capture
tools/trans.sh 3 40 out.png next                       # headless: frame 40 of the 3->4 handoff
python3 tools/qa.py                                    # behaviour checks -> captures/qa-report.txt
python3 tools/captures.py                              # rebuild every capture (+ concept side-by-side, gif)
python3 tools/responsive.py --jobs 3                   # viewport matrix -> captures/responsive/ (one sheet per scene)
rive . --viewport=1280x720 --screenshot=out.png --advance=150   # any size: the default --fit=layout resizes the artboard
/usr/bin/python3 tools/grain.py                        # regenerate assets/images/grain.png (needs Pillow)
```

**Host fit:** use the runtime's **layout fit** so the artboard is resized to the canvas; the file lays itself out for that size (see "Responsive layout" below). Do not use `Fit.contain` any more: it would letterbox the 390×844 authoring size instead of reflowing.

## Structure

- **Artboard `Parlance Recap`** (main, authored at 390×844, laid out at any size). A `Viewport` layout box fills the artboard (its computed size feeds the layout solver, and it carries the progress row); everything else sits in a 390×844 `Stage` box at the origin whose content is mapped onto the real canvas by bound frame nodes. From top to bottom of the hierarchy: chrome (wordmark, year, progress row, a `Controls` focus scope holding 5 buttons, the nav hit regions), the mouth hit target, the `Dwell Clock` placement, the hero-reveal driver, the quote aperture (the clip source shared by every scene), the **persistent motif** (`Motif A` is a persimmon comma-tailed speech form and `Motif B` a lilac one, each with a laughing face and an all-cubic, morphable body), then `Scene 10` … `Scene 1`, and under them the `Transition plate` (the colour seen around the opening/closing quote). Each scene node holds a grain overlay, its copy, foreground, mid and background art. All art is layered editable vectors (PointsPath, parametric shapes and font glyphs); the only raster is one 29 KB paper-grain tile (`assets/images/grain.png`) drawn with the overlay blend.
- **Component `Dwell Clock`** (nested). It owns the auto-advance timer. Its speed is bound to `1/clamp(autoAdvanceSeconds, 4, 60)` and its `isPaused` to `UserRecap.isPaused`.
- **Component `Share Card Wide`** (nested, 766×300), the same card from the same builder with the persona on the left and the five tiles in a 3×2 grid. It is shown whenever the canvas is wider than tall. Render whichever of the two the host wants for the share snapshot.
- **Component `Share Card`** (nested, 342×556). This is the collectible summary card: wordmark, year, persona emblem, title and the five aggregate tiles. It has its own state machine (assembly, privacy flags, persona pick, new-user mode). It has no chrome, so a host can render it alone for the share snapshot.
- **State machine `Recap`** has these layers:
  - `Sequence`: about 110 states. Per scene there are forward and back gates, In, Back-In, Reduced-motion-In, Dwell, Out, Out-Back and reduced-motion fades, plus carry gates.
  - `Idle loops`
  - `Persona` and `Persona idle`
  - `Chrome theme`
  - `Controls mode`
  - `Pause icon`
  - 8 × `Segment k visibility`
  - `Summary copy`
  - `Press (tap vs hold)`
  - `Mouth tap`

## Single global view model `UserRecap`

There is exactly one view model, `UserRecap`. Every scene, the nested Clock and Share Card, the summary, the progress row and the persona visuals bind to the same instance. The nested artboards inherit the root's data context. **Rive-specific note:** I bound `UserRecap` to the main artboard and did not use Rive's `viewModelType="global"`. The reason: a Rive *global* VM has a single instance and cannot be reached by `--data`/instance selection, which would make fixtures and host instance swapping impossible. Functionally it is still one shared instance. Exported instances: `Sample fixture` (default), `New user fixture`, `Extreme fixture`.

All contract properties from the brief exist with these names and types. Colour strings are `ViewModelPropertyColor` (ARGB): the adapter maps `#RRGGBB` to `FFRRGGBB`.

**Ownership**
- *Host writes:* user data, the `showScreenN` flags, labels and localized copy, `locale`, `autoAdvanceSeconds`, `autoAdvanceEnabled`, `isPaused` (also on app background or while sharing), `reducedMotion`, `soundEnabled`, the `share*` flags, `personaIndex`.
- *File writes (host reads):* `currentScreen` (canonical 1–10), `screenProgress` (0–1 dwell, written by the Clock), and `personaName`, `personaDescription`, `personaColor`. The file derives these three atomically from `personaIndex`; unknown or non-integer indices fall back to row 0.
- *The file also writes `isPaused`* on Pause/Play, Space, and hold-to-pause.

**Adapter additions (not in the brief's table)**

| name | type | purpose |
|---|---|---|
| `groupSeparator` | string | locale digit-group separator (`,` for en-GB, `.` for de, ` ` for fr). The file groups digits itself. |
| `personaName0..3`, `personaDescription0..3` | string | localized persona table. The Persona layer copies the row for `personaIndex` into `personaName`/`personaDescription` and writes `personaColor`, all in one state entry, so the label, palette and emblem never disagree. |
| `goNext`, `goPrevious`, `requestReplay` | trigger | host-callable navigation (the same triggers the buttons, keys and taps fire). |
| `layoutBreakpoint` | number (default 768) | **contract addition, host-writable.** The landscape layout is used when the artboard is at least this wide (see "Responsive layout"). |
| `_dwellStart`, `_dwellStop`, `_heroReveal`, `_focusIndex`, `_pointerDown`, `_pressSide`, `_finishedLatch`, `_mouthTap`, `_focusVisible` | internal | animation playheads and latches. The underscore marks them private, and hosts should not write them. |
| `_vw`, `_vh`, `_land`, `_split`, `_k`, `_m`, `_top`, `_bot`, `_sc`, `_a1x` … `_a9s`, `_mixA`, `_mixB`, `_motifMap`, `_mixMouth` | internal | the responsive layout solver's state (real size, orientation, margins, scales, art frames) and the keyed blends of the global motif between scene art space and full-canvas cover space. Written by the file every frame; hosts must not write them. |

**Formatting:** counts are clamped with `max(0, round(x))` in converters. Three tiers (<1,000, <1,000,000, larger) build `1,860` or `1,234,567` from `groupSeparator`, and `fitFontSize` handles extreme widths without compacting. Hero numbers count from 0 to the value through the bound `_heroReveal` driver, so no placeholder digits flash. **The host adapter must:** clamp NaN/∞ (converters can't), choose singular or plural unit strings (`screenNUnit`), compose the localized `introHeadline`/`periodLabel` from year and name, and provide accessible full-value text and announcements. `tools/fixture.py` is a reference adapter for previews.

**Events**
- `screenChanged`: fires on every scene entry. Its payload is the custom property `screen`, bound to `currentScreen`. Read `currentScreen` as the source of truth.
- `shareTapped`: fires from the Share button or Enter. The host owns the capture and the platform share sheet. Only the event wiring is supplied; there is no real share integration. Set `isPaused=true` while the sheet is open and restore the previous value afterwards.
- `recapFinished`: fires once, the first time the summary settles. Replay clears the latch.
- `mouthTapped`: fires on the signature interaction. Its payload is `soundEnabled`. The file is silent; if `soundEnabled` is true, the host may play an opt-in sound.

The headless CLI does not report plain events. `qa.py` therefore verifies the state each firing state writes, and confirms that the events exist in the `.riv`.

## Responsive layout

The recap adapts to any canvas. It has two layouts chosen by a width breakpoint, and each one reflows continuously for every size on its side of the breakpoint. Nothing is letterboxed.

### The rule

- **Landscape layout when the artboard is at least `layoutBreakpoint` wide (default 768); otherwise the portrait layout.** This is a pure width rule. 768×1024 and 820×1180 get the landscape layout, and 667×375 and 740×360 get the portrait layout.
- `layoutBreakpoint` is a new `UserRecap` number property (a contract addition; see the adapter table). The host can tune it. Values ≤ 1 make every size landscape.
- The orientation is derived from the real artboard width at runtime and re-evaluated whenever the canvas is resized, including across the threshold mid-scene. The current scene, dwell progress, pause state and focus are kept. The new layout settles within one or two frames (`qa.py` checks 19a and 19b).

### What each layout does

- **Portrait (stacked):** the chrome sits on top (wordmark, year, and a progress row across the real width). Below it are the top copy block, the illustration, the bottom copy block (caption, or the hero number on scene 7) and the control bar.
  - Copy uses its own scale `_sc`. It follows the width and, more gently, the height, clamped to 0.7–1.3, so a 16 pt caption never drops below ~11 pt.
  - The art is fitted into whatever height remains and is never wider than the canvas.
  - At 390×844 every frame is the identity, so the original composition, hit targets and the 26 original checks are unchanged.
  - On a portrait canvas that is wider than tall (a phone on its side: 667×375, 740×360), copy and art go side by side with the compact portrait chrome. Stacking would push text under the readable minimum there.
- **Landscape (side by side):** a copy column (number, unit, headline, caption, stacked and vertically centred, with at least 5% of the band free above and below) and an art column (illustration fitted and centred).
  - The content is capped at 2.4× the band height and centred, so 2560×1080 still reads as one composition.
  - Scenes 5 and 9 are mirrored (art left, copy right).
  - **Persona (9):** the emblem stage takes the left 55% and the title, label and description sit right.
  - **Summary (10):** a narrower copy column plus the **`Share Card Wide`** component (persona left, five tiles in a 3×2 grid right). On a tall landscape canvas (768×1024, 820×1180) the tall card is used, because it can use the height there.
- **Everything follows the real size:**
  - Backgrounds bleed 10% past every edge, so a handoff that shrinks the scene about the centre never shows a gap.
  - The paper grain tiles over any canvas without changing grain size.
  - Margins, the progress row, the controls (≥ 44 pt at every tested size; Continue narrows on small phones), the back/next tap thirds and hold-to-pause all use the real width.
  - Scenes 6 and 7 extend their ribbons and sentence line past the edges. Side by side, these are clipped at the art column, so they never run under the copy.
- **Full-canvas transitions:** the global speech forms, the quote aperture and the scene-3 lips each have a frame that blends between the scene's art space and a *cover space* (the 390×844 frame scaled to cover the canvas).
  - The blend weights `_mixA`, `_mixB` and `_mixMouth` are keyed alongside the poses. An elongating cover therefore always fills the whole viewport, while the same forms sit correctly in the art of scenes 1, 2, 3 and 9.
  - The carries 1→2 and 2→3 key `_motifMap` from one scene's art space to the next.
  - `qa.py` checks the cover edges at 2560×1080, 740×360, 820×1180 and 667×375.

### Mechanism (pure RML, still no scripts)

1. A `Viewport` layout box fills the artboard and binds its **`computedWidth` / `computedHeight` (keys 810/811) target → source** into `_vw` / `_vh`.
2. A hidden **layout solver** turns those into a small set of view model values: orientation, side-by-side flag, chrome scale `_k`, margin `_m`, content band `_top` / `_bot`, stacked copy scale `_sc`, and the art frames of scenes 1, 2, 3 and 9.
   - Each solver value is a node whose `x` is bound from a `DataConverterFormula` and written back with a `direction="true"` bind.
3. Every scene is `anchor (canvas centre) > root (keyed handoffs, aperture clip) > pivot > frames`. There is one frame per layout block: top copy, bottom copy, art, and the wide card.
   - Each frame's `x`, `y` and scale are bound to a formula: the stacked placement × (1 − `_split`) + the side-by-side placement × `_split`.
   - The keyed animation inside the frames is untouched, in design coordinates.
4. Chrome, controls, tap regions, the plate and backgrounds bind their position or size to the same values. The control positions also read `currentScreen` to switch between story and summary controls.
5. The formulas are generated by `tools/generate.py` (`LAYOUT` table, `stack_frames`, `split_frames`). They are emitted with minimal brackets and deduplicated.

### Host setup

- Present the main artboard with the runtime's **layout fit**, so the artboard is resized to the canvas and the file reflows. Do not use contain or cover.
  - The option names differ per runtime: on the web it is a `Layout` with `fit: Fit.Layout`; the native and Flutter runtimes have a layout fit as well.
  - Check the Rive runtime docs for the exact option, and for the layout scale factor that maps CSS or device pixels to artboard points.
  - The CLI's default `--fit=layout` behaves the same way.
- Keep the drawing surface sized to the canvas on resize (on the web, `resizeDrawingSurfaceToCanvas()`), so the artboard receives the new size.
- Optionally write `layoutBreakpoint`. Do not write the `_`-prefixed solver properties.
- For the share snapshot, render `Share Card` (tall) or `Share Card Wide` alone; both read the same instance.

### Size limits tested

The matrix in `captures/responsive/` has one contact sheet per scene (`scene-01.png` … `scene-10.png`, every size, settled), five mid-transition sheets (`transition-carry-1to2`, `-signature-3to4`, `-handoff-5to6`, `-persona-8to9`, `-summary-9to10`) and `resize-mid-scene-3-landscape.png` (written by `qa.py`):

- **Portrait:** 320×568, 360×640, 390×844, 430×932, 600×960, 767×1024, 667×375, 740×360.
- **Landscape:** 768×1024, 820×1180, 1024×768, 1280×720, 1440×900, 1920×1080, 2560×1080, 1366×600.

The extreme fixture, the new-user summary and reduced motion were also checked at 320×568, 390×844, 740×360, 768×1024, 1280×720 and 1366×600. The intended range is about 320×360 up to ultra-wide; below ~320 wide or ~340 tall the minimum scales start to overlap.

Results across the matrix: backgrounds, the progress row, the tap thirds and every handoff cover reach all four edges; controls stay ≥ 44 pt; copy, art and controls do not collide except for the scene-4 word cascade brushing the headline at 320×568. The weakest sizes are the tall landscape canvases (768×1024, 820×1180; see below).

### Compromises

- **Tall landscape canvases** (768×1024, 820×1180) keep the side-by-side composition with its width-limited columns, so copy and art are moderate in size with generous empty bands above and below.
- **The share card's micro labels** (11 pt tile labels) scale with the card. At 320×568 (tall card at ~0.55) and 667×375 or 740×360 (wide card at ~0.55) they render around 6 pt; the numbers, title and persona stay legible. The host's share snapshot renders the card at full size.
- **Short phone-landscape canvases** (740×360) bring copy to the 0.68 floor: captions are ~11 pt.
- **The stacked arrangement scales art independently of copy.** On 320×568 the illustrations are at ~45–55%. Scene 4's word cascade, authored beside the headline, keeps that relationship only approximately at small sizes.
- **Discrete switches:** the side-by-side portrait arrangement switches at aspect 1:1, and the orientation switches at the breakpoint. Crossing either snaps to the other arrangement; it does not morph.
- **Size of the file:** the `.riv` grew from 1,982,450 to 2,116,189 bytes (+134 KB, +6.7%). About 60 KB is the second card artboard, and most of the rest is layout formula tokens.
- **The mid-scene resize check** uses a test-only harness artboard that nests the recap in a box with a keyed size, because the headless CLI cannot resize mid-run. `qa.py` builds it in a temp copy of the project, so it is not in the shipped `.riv`.


## Behaviour (all verified in `captures/qa-report.txt`)

- **Navigation:** the right two-thirds of the story area advances and the left third goes back. Holding pauses (350 ms threshold), and releasing resumes without a tap. Previous, Pause/Play and Continue have 52 pt targets; the summary shows Replay and Share. Left/Right navigate and Space pauses. Tab and Shift+Tab move focus (a persimmon ring shows it), and Enter activates the focused button. Buttons carry `SemanticData` labels bound to the label strings.
- **Hidden scenes:** skipped in both directions. The progress row is a flex row with `display:none` per hidden segment, so exactly the visible count renders. Intro and summary are always eligible, whatever their flags say. With no eligible metric scenes, the flow goes intro → welcoming summary (`emptyHeadline`) with a neutral motif and no persona.
- **Auto-advance:** 7 s by default, counted after the entrance settles and clamped to at least 4 s. `autoAdvanceEnabled=false` holds the current scene. Pause freezes the timer, the idle loops and the persona idle while keeping progress. The summary never auto-loops.
- **Rapid taps:** a tap during an entrance skips straight to the next scene, and a tap during an exit skips one further (entrances cut in; no cross-blend). Five quick taps from scene 1 land on scene 6, and no scene is entered twice.
- **Reduced motion:** every arrival uses the scene's final pose, a 200 ms fade and no camera or motif movement. The idle loops are frozen and every control still works.
- **Privacy:** the card hides the name unless `shareIncludeName` is set. `practiceMinutes` is treated as the one sensitive aggregate and shows "—" unless `shareIncludeSensitiveValues` is set. No recordings, transcripts or locations appear anywhere.

## Motion

Timings are at 60 fps.

- Scene entrances follow the score: 0–200 ms is the quote aperture's dots → quotation mark (the anticipatory gesture), 200–1,400 ms is the hero and count, then the copy resolves word by word by about 1.8 s, then a restrained idle runs.
- Handoffs are 450–850 ms (generic forward 467 ms, signature 733 ms, reverse 500 ms). The reverse direction is the signature played backwards: the scene closes into a quotation mark, then the lilac form deflates, with a compressed rebuild.

**Hero sequences**
1. Intro: the cover collapses into the motif pair, and the wordmark letters stretch out of an envelope (text modifier).
2. Scene 3: an elastic mouth opens around the rolling numerals.
3. Scene 4: multilingual word blocks cascade into giant quotation marks.
4. Scene 9: the persona reveal. The motif pair orbits and winds up, then collapses into the emblem. Each persona has its own emblem silhouette and choreography: welcoming faces with speech marks, a stacked quotation-mark archive, an open-parenthesis ear with sound ripples, and an elastic exclamation mark with squash and stretch.
5. Scene 10: the summary card assembles.

**Continuity carries**
- 1→2: the two speech forms travel down into the conversation.
- 2→3: the persimmon form flies to centre stage, and its mouth becomes scene 3's mouth.

**Signature transition:** a speech form elongates (true vertex morph) until it fills the frame, then the next scene opens through a quote-shaped aperture (two dots sprout comma tails, then the quote opens). 3→4 is the hero version, where scene 3's lips morph into the speech bubble first; 4→5 … 9→10 use the motif forms. The reverse closes the scene into a quotation mark and the lilac form deflates. Details under "Refinement pass".

**Signature interaction:** tapping the illustrated mouth in scene 3 or 2 plays a silent elastic squash (in scene 3 the tongue also wags). Its opaque hit target cancels the story tap, so it cannot navigate.

## Measurements

These come from the CLI on this Mac. The headless renderer is not a phone, so treat the numbers as indicative.

- `.riv`: **1,982,450 bytes** (was 1,629,196 before the refinement pass). About 1.4 MB is fonts; most of the +353 KB is keyframes (the vertex morphs key 6 properties × 10 vertices per form, and every cubic key carries its own interpolator), plus 29 KB grain and 5 KB CJK subset.
- `rive . --bench=600` (scene 1, 390×844 @1x): advance mean 0.063 ms (p95 0.46 ms), render mean 0.145 ms (p95 0.15 ms; one 24 ms first-frame outlier). Before: 0.032 / 0.060 ms. Still far under the 16.7 ms budget for 60 fps. No measurement was taken on a real device.
- Objects: main artboard 54,681 (was 17,637; ~24k are keyframes), Share Card 2,321. Particle and token pools stay bounded at 7–15 objects per scene, so nothing scales with a raw count.

## Unsupported or substituted techniques (honest list)

- **Global VM:** uses one shared bound instance rather than Rive's `global` type (see above).
- **Locale formatting:** there is no locale-aware converter, so the file groups digits from the host's `groupSeparator`. Plurals and decimals beyond integers are the adapter's job.
- **Dwell timing:** an `AnimationState` cannot bind its speed, so the dwell timer is a nested artboard whose bindable `speed` scales a 1 s timeline. The timeline writes `screenProgress` and fires `goNext`.
- **State-machine writes:** a state machine can't write a VM number from a timeline, so animated drivers use two-way binds (`_heroReveal` on a hidden node's `x`, `screenProgress` on the Clock driver).
- **Morphs:** the motif forms, the scene-3 lips and the quote aperture now morph for real: every vertex (position and both handles) is keyed between same-count all-cubic paths (lips → bubble → elongated cover; dot → comma). The laughing faces are skinned to bones (see "Fix pass"). Other secondary motion still uses node squash/stretch, TrimPath reveals, text modifiers and `TextFollowPathModifier` (scene 6 ribbons).
- **Texture:** the concept's tactile rendering is approximated with gradient + inner-shadow (`Feather inner`) paints on each form, feathered highlights and ground pools, and one overlay-blended raster grain tile per scene. The grain sits above the art and copy but the overlay blend leaves near-white and near-plum (i.e. the type) almost untouched.
- **Audio:** no audio asset is shipped. The sound is opt-in and host-played via `mouthTapped`.

## Remaining limitations

- No `.rev` export yet (needs `rive login`).
- The file has not been opened in the editor or on a device, so frame rate there is unmeasured.
- Long copy no longer reaches the illustrations: units are one fitted line, headlines a fitted box of at most three lines, captions sit on the control bar, intro/summary copy is bounded. The cost is that `extreme.json` headlines render smaller (about 30 px instead of 39).
- RTL was not verified (no RTL locale required).
- (Fixed) The focus ring is now a `:focus-visible` ring: `_focusVisible` is set by Tab / Shift+Tab and cleared by any pointer press, so pointer users no longer see a permanent ring on Continue.
- `screenChanged`'s `screen` payload is bound at fire time, so read `currentScreen`.
- The scene-6 weave is faked with a trimmed overlay segment.
- Plain events are not observable headlessly, so verify them in a host.

## Refinement pass (concept match + motion)

Goal: match `concept.png` (screens 2, 4, 9) more closely, carry that art direction through all ten scenes, and push the motion from "works" to kinetic typography. The contract (one `UserRecap` VM, property names, events, ten scenes, four personas, privacy flags, reduced motion, hidden-scene skipping, fixtures, Right-arrow navigation, 390×844) is unchanged, and `tools/qa.py` still passes 26/26 without edits. `captures/concept-vs-build.png` puts each concept screen next to the settled build scene.

**Face rig (all generated by `face()` / `Talk` in `tools/generate.py`; pure RML, still no scripts).** Every
speech-form face (motif A/B, persona 0's pair, persona 2's voice bubble) is now a rig rather than one scaled node:

- *Mouth:* an 8-vertex D-shape skinned (`Skin`/`Tendon`/`CubicWeight`, see `rive docs rigging`) to four bones:
  upper lip, jaw, left and right corner. Keying the bones deforms the vertices into real shapes: `a`, `o`, `e`,
  `i`, `u`, `l`, `m`, a closed listening grin and the laugh. Each syllable opens with an overshoot ease, then
  half-closes before the next one. Syllable lengths wobble, so speech never ticks evenly. A "jaw override" parent
  bone lets transitions open the mouth on top of whatever the idle layer is doing.
- *Teeth and tongue:* both are clipped to the deforming mouth (`ClippingShape`). The teeth ride the upper lip and
  slide up out of view when the mouth shuts. The tongue is a separate path skinned to a root and a tip bone, so it
  lifts on `l`/`e`, curls and wiggles through laughs, sways with speech and drops away when the mouth closes.
- *Eyes:* each eye is a skinned oval on shared lid and corner bones. A fifth "lid crease" bone carries the lower
  lid's inner handles, so a squint arches up into the concept's `^` closed eyes. The eyes blink (fast close, slow
  open) and soften while listening. They squint and the new brows lift while laughing. The gaze, with a slight head
  turn, shifts between the partner and the viewer. Glints hide on blinks and squints.
- *Follow-through:* the lips node squashes and stretches 3 frames behind the jaw, and the cheeks (new feathered
  blush) lift and squash 4 frames behind the smile. Both use overshoot eases.
- *Choreography:* `converse()` is a turn-taking exchange. One form talks while the other listens. Both laugh, the
  second one a beat late. Then they swap roles. Each character has its own tempo, blinks and glances. Scene 1 opens
  with the lilac form talking, scene 2 with the persimmon one. Persona 0 has a 480-frame loop (a conversation, then
  a quieter shared laugh). Persona 2's voice bubble runs `monologue()`. Every idle channel starts and ends at rest,
