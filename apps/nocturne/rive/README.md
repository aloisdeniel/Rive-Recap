# Nocturne — 2026 recap (Rive)

A ten-scene, Wrapped-style stargazing recap for the fictional app **Nocturne**, authored as RML with the Rive CLI 1.6.0.
All dates and figures are fictional fixture data. The skies are decorative: none of them is a real sky map.

```
apps/nocturne/rive/
  rive.yaml              project (name: nocturne-recap, main artboard "Nocturne Recap")
  rml/00_data.rml        UserRecap view model (+3 fixture instances), converters, fonts, script asset
  rml/10_main.rml        "Nocturne Recap" artboard: stage, chrome, motif, gestures, the sequencing state machine
  rml/20_aperture.rml    "Aperture Motif" reusable component (iris + observatory reticle)
  rml/30_scenes.rml      ten scene components ("Scene 1 · Invitation" … "Scene 10 · Summary")
  clock.luau             dwell timer (auto-advance), the only script
  assets/fonts/          Space Grotesk (variable) + IBM Plex Mono, with OFL licence texts
  fixtures/              sample.json, new-user.json, extreme-long-copy.json
  tools/                 generate.py (+ rml.py DSL), interaction_tests.py, capture_all.py, shoot.py, preview.sh
  captures/              review stills, transition frames, motion preview (see below)
  build/nocturne-recap.riv   runtime export (unsigned, see "Scripts and signing")
```

The `rml/` files are generated by `tools/generate.py`, which keeps the large, regular parts consistent: ten scene state
machines, navigation transitions that respect visibility, and keyframe completion. Either edit the generator and
re-run `python3 tools/generate.py`, or hand-edit the RML and stop regenerating.

## Preview

```bash
cd apps/nocturne/rive
rive .                                   # live previewer; uses the default "Fixture" instance
tools/preview.sh new-user                # same, with a fixture pushed into UserRecap via --data
tools/preview.sh extreme-long-copy
tools/preview.sh sample --data=reducedMotion=true --data=personaIndex=3
```

* **Tap** the right two-thirds to go forward and the left third to go back. **Hold** anywhere in that area to pause, and release to resume. Releasing a hold never counts as a tap.
* **Buttons:** Previous, Continue and Pause/Play; on the summary, Share and Replay.
* **Keyboard:** ←/→ navigate, Space toggles pause, Tab/Shift+Tab move focus (shown as a dashed amber ring), and Enter activates the focused button.
* **Scene 1 finder:** drag the small reticle on the disk. It stays inside a circular bound and reveals extra stars through its lens. It has its own opaque hit area, so dragging it never navigates.

```bash
rive . --verify && rive inspect . --summary     # both clean: 0 errors, problems: []

```

## Architecture

* **One view model instance.** `UserRecap` has exactly one instance, bound to the root artboard. Every scene and the
  motif are *plain* (non-stateful) nested artboards, so they inherit that same instance; no component owns a copy of
  any statistic. The file also contains instances named `Fixture` (the default), `NewUser` and `Extreme`. These are test
  data a host can select by name; production should create one instance and write into it.
  Rive's `viewModelType="global"` was not used: the CLI's `--data` and the usual host binding APIs target the
  artboard's bound instance, and a global cannot be swapped for a fixture. In practice it behaves as the single global
  model the brief asks for.
* **Sequencing state machine `Recap`** (main artboard), with these layers:
  * `Sequence`: states 1–10 plus "10 settled". Entering state *k* writes `currentScreen = k` and fires `screenChanged`.
    `navNext` and `navPrevious` transitions jump to the nearest *eligible* scene in either direction, with every
    combination of `showScreenN` flags generated explicitly. The same transitions write `navDirection` (+1 or −1).
    1.8 s after reaching the summary, and only while `recapFinishedFired` is false, the machine moves to "10 settled",
    fires `recapFinished` and sets the latch. `navReplay` returns to 1 and clears the latch.
  * `Gesture (tap / hold)`: press, then either release within 380 ms (fires `navNext` or `navPrevious` by side) or hold
    (`isHolding = true` until release, with no tap).
  * `Motif`: the travelling aperture. Through AnyState it moves to "Through k" whenever `currentScreen ≠ motifPose`.
    Forward, it closes to a pupil, holds, then opens onto the new pose. Back is a deliberate alternate: it opens from a
    larger scale with the opposite spin. Under reduced motion it snaps straight to the pose.
  * `Ambient` (sky twinkle, lodestar sway): frozen while paused or holding, static under reduced motion.
  * `Finder Invite`, `Boot` (initial keyboard focus on Continue).
  * `Persona Mapping`: the derived binding described under "Persona mapping" below.
  * `Eligibility`: writes `hasStats` (true when any of screens 2–8 is shown).
* **Scene components**, each with its own machine reading the inherited `currentScreen`, `navDirection`,
  `reducedMotion`, `isPaused` and `isHolding`. States: Hidden → Enter forward or Enter back → Idle (loop) ⇄ Frozen
  (paused) → Exit forward or Exit back → Hidden; Static is the reduced-motion state. Every Enter, Hidden and Static
  timeline is auto-completed with the settled value of every property any timeline in that scene touches. That is why
  rapid navigation always settles cleanly, with no orphaned or stacked poses.
* **Dwell clock** (`clock.luau`, a 1×1 `ScriptedLayout`): waits for the entrance to settle (1.6 s, or 0.35 s under
  reduced motion), then fills `screenProgress` over `clamp(autoAdvanceSeconds, 3, 60)`. Non-finite values fall back to
  7 s. It fires `navNext` once per scene. It never runs while `isPaused` or `isHolding` is set, never when
  `autoAdvanceEnabled` is false, and never past the summary. Progress is kept across a pause.
* **Progress segments**: a flex row of ten boxes. Box *k* (for 2–9) has `displayValue` bound to `!showScreenk`, so
  hidden scenes drop out of the row and the remaining segments widen. Exactly as many segments render as there are
  eligible scenes. The fill of each box is `scaleX = clamp(currentScreen − k + screenProgress, 0, 1)`.

### Motion score (all scenes)

| Phase | Time | What happens |
|---|---|---|
| Orient | 0–200 ms | The motif's pupil closes and holds (the signature transition), and the outgoing scene recedes into it |
| Hero + count | 200–1,200 ms | The iris opens on a new scale of sky. The hero illustration builds while the number counts from 0 to the bound value; the count is driven by the scene timeline (`fxCountN` playhead × value), so it is in step with the art |
| Resolve | 1,200–1,800 ms | Unit label, amber rule, headline, support |
| Dwell | host-set | Restrained loops only: twinkle, slow star-trail rotation, meteor pool, orbit drift. All are frozen while paused |
| Handoff | 450–850 ms | Forward: about 260 ms mix into a closed pupil, a 200 ms hold, then the opening. Back: a distinct reverse (larger scale, opposite spin, copy drops in from above) |

* **Hero sequences:** the Invitation disk and wordmark reveal; Nights (iris opening on a star field whose stars kindle
  in step with the count); Lunar (successive masked illumination, new moon → crescent → half → gibbous, with nine
  session glyphs); Meteors (a bounded pool of five meteors, with persistent exposure trails); the Persona reveal; and
  the Summary assembly.
* **Continuity objects:**
  1. The aperture motif: one nested instance travels through all ten scenes. It is the disk frame on 1 and 7, the
     iris on 2, the instrument hub on 3, the midnight pupil on 4, the finder on 5, the observation port on 6, the
     sketch lens on 8, the emblem frame on 9 and the share-card seal on 10.
  2. The amber **lodestar**: the same object becomes the ring marker, the arc head, the constellation anchor, the
     meteor radiant, the lunar glint, the pen nib, the persona crown and the card spark.
  3. A parallax sky whose offset and scale change with each pose.
* **Persona reveal:** the pupil "breathes" twice before opening. Each persona has its own emblem *and* choreography:
  * 0, nested nebula aperture: rings ripple outward and counter-rotate around a nested Aperture instance.
  * 1, lunar disk: the disk rises with a back-ease while phase moons orbit in.
  * 2, orbital reticle: the reticle snaps with a damped overshoot, the orbit draws, and the planet slides along the projected ellipse.
  * 3, meteor arc: a fast arc sweep, with a midnight eclipse disk and corona.

## Binding and event contract

All names are on `UserRecap`. Unless noted otherwise, **host** means the host writes the property and the file only reads it.

| Property | Rive type | Owner | Notes |
|---|---|---|---|
| userName, periodLabel, locale | String | host | `userName` wraps to one line and truncates at a word boundary with an ellipsis. `locale` is informational: the file does no locale formatting |
| year | Number | host | Rendered as an integer |
| observationNights, objectsLogged, observationHours, constellationsLogged, meteorSightings, moonSessions, sketchesMade | Number | host | Rendered through `max(0, round(x))`. The hero uses `fitFontSize`, so very large values shrink only the hero number |
| personaIndex | Number | host | 0–3. Any other value falls back to 0 |
| personaName, personaDescription | String | **file** (derived) | Written by `Persona Mapping` whenever `personaIndex` changes. To localise, write them after setting the index |
| personaColor | **Color** (ARGB) | **file** (derived) | The brief's `"#BCE4E8"` string becomes a native colour. Host adapter: `"#RRGGBB"` → `0xFFRRGGBB` |
| autoAdvanceSeconds, autoAdvanceEnabled | Number, Boolean | host | Clamped to 3–60 s in the clock |
| isPaused | Boolean | host + file | The Pause/Play button and Space toggle it. The host sets it for background, share sheet, etc. |
| reducedMotion | Boolean | host | Final values, static heroes, and 220 ms opacity-only scene changes |
| soundEnabled | Boolean | host | Reserved. The file ships no audio and is fully silent |
| currentScreen | Number | **file** | Canonical one-based scene id. Read-only for the host |
| screenProgress | Number | **file** (clock) | 0–1 for the current dwell |
| shareIncludeName | Boolean | host | Shows `userName` on the share card. Default false |
| shareIncludeSensitiveValues | Boolean | host | Reserved. The card holds only the persona and five aggregate stats, by construction, so no location, recording or annotation data exists to reveal |
| continue/previous/pause/play/share/replayLabel, intro*, summary*, empty*, personaLabel, screen2–8 Headline/Support/Unit | String | host | Every visible string except the decorative wordmark and the coordinate ornaments |
| showScreen1…showScreen10 | Boolean | host | 2–9 control eligibility. 1 and 10 are always eligible, which is the safe intro → summary path |

**Additions** (in the file, documented here):

| Property | Type | Owner | Purpose |
|---|---|---|---|
| navNext, navPrevious, navReplay | Trigger | host or file | Navigation. A host may fire them for its own keyboard or remote handling |
| navDirection | Number | file | +1 forward, −1 back. Chooses forward or reverse choreography |
| isHolding, pointerDown, pressSide | Boolean, Boolean, Number | file | Hold-to-pause gesture state |
| recapFinishedFired | Boolean | file | Completion latch. Replay clears it |
| hasStats | Boolean | file | False when no stats are eligible: welcoming summary variant, no stat grid |
| personaSlot | Number | file | Resolved persona row (0–3) that drives the emblem |
| motifPose | Number | file | Internal: the motif's current pose |
| focusedControl | Number | file | 0 none, 1 Previous, 2 Pause, 3 Continue, 4 Share, 5 Replay. Drives the focus ring |
| captureMode | Boolean | host | Hides all chrome (progress, controls, header) for a clean share-card snapshot |
| fxCount2…fxCount8 | Number | file | Internal count-up playheads (0–1). Never user data. Host: do not write |

**Events** (on the main artboard):

| Event | When | Payload |
|---|---|---|
| `screenChanged` | On entering every scene state, including the first | Custom number `screen` bound to `currentScreen`. Treat the payload as best-effort: it is bound in the same frame `currentScreen` is written. **Read `currentScreen` after the event** |
| `shareTapped` | Share button: click, Enter or screen-reader tap | None. The host owns capture and the platform share sheet |
| `recapFinished` | Once, 1.8 s after the summary first settles. Re-armed only by Replay | None |

Verified counts, using a probe build that swaps these events for logged `OpenUrlEvent`s (`NOCTURNE_EVENT_PROBE=1 python3 tools/generate.py`):

| Scenario | `screenChanged` | `recapFinished` | `shareTapped` |
|---|---|---|---|
| 90 s auto run | 10 | 1 | — |
| 7 rapid taps | 1 + 7 (no duplicates) | — | — |
| Back from summary, then forward again | — | still 1 | — |
| Share, Replay, then auto run again | — | 2 (re-armed by Replay) | 1 |

**Host adapter responsibilities**

* Parse `personaColor`.
* Clamp negatives, NaN and ∞ before writing numbers. The file clamps negatives and rounds for display, but cannot
  detect NaN.
* Supply localised and pluralised unit strings and labels. The file has no plural rules or digit grouping, so
  `1284567` renders without separators (see Limitations).
* Map hidden or unknown metrics to `showScreenN = false`. Zero stays a valid number.
* Set `showScreen9 = false` when there is no persona evidence.
* Set `isPaused` while the app is backgrounded or the share sheet is open, and restore the previous value afterwards.
  The file never auto-advances while paused.
* Set `captureMode = true`, wait one frame, snapshot the summary, then reset it.
* Give the runtime keyboard focus, or rely on the file's initial focus on Continue.
* Expose screen-reader announcements for `currentScreen` changes. Buttons carry `SemanticData` role=button.

## Unsupported techniques and substitutions

* **Iris blades:** there is no mesh or 3D. Nine flat blade shapes pivot on the rim, clipped to a circle, and their
  rotation follows `asin(r/R)` so the hole radius is linear in time. One timeline, `Iris`, is scrubbed by a
  `NestedRemapAnimation` from the main timelines.
* **Count-up:** a text run cannot be keyed to a number. Instead a hidden node's `x` is keyed 0 → 1 and bound
  target-to-source into `fxCountN`, and the hero text uses the formula `round(value × fxCountN)`.
* **Booleans driving layout or opacity:** booleans cannot bind to `displayValue` or opacity, so they pass through a
  converter chain (negate → ToString → ToNumber).
* **Hit regions on swapped buttons:** opacity does not disable hit-testing, so Share and Replay versus Continue and
  Pause are moved off the artboard by a formula on `currentScreen` rather than faded.
* **Lunar illumination:** there is no boolean path subtraction, so it is built as a stack of lit and dark ellipses and a
  dark half-disk inside one circular clip, with the ellipse widths keyed.
* **Raster grain:** none. Everything is vector, with no images.
* **Responsive layout:** the composition is fixed at 390 × 844. Other screens use a `contain` presentation, which
  letterboxes and centres the artboard, rather than a reflow. It was captured at 320 × 568, 430 × 932 and
  1440 × 900 (`captures/viewports/`). Safe margins are 28 pt at the sides, the header sits above y = 100 and the
  controls below y = 756.

## Scripts and signing

`clock.luau` is the only script. Local builds (`--once`) are **unsigned**: they play in the CLI previewer and in
runtimes built with tooling enabled, but web runtimes and the CDN reject them. For a web or production build, either:

* build with `rive . --publish`, which needs `rive login`, or
* set `autoAdvanceEnabled = false` and let the host drive `screenProgress` and fire `navNext`. Everything else is pure
  RML and needs no signing.

## Exports

* `build/nocturne-recap.riv` comes from `rive . --once`.
* `build/nocturne-recap.rev` was **not produced**. `rive . --once --rev=build/nocturne-recap.rev` stops with `Not logged in.
  Run: rive login`. After logging in, run that command to write the editor file.

## Honest limitations

* **Locale formatting:** there are no digit-grouping separators, plural rules or compact labels in the file. The hero
  shows raw integers, and accessible full values and plural strings are the host's job.
* **Event payload:** the `screenChanged` payload timing is unverified (the CLI does not log plain events). Read
  `currentScreen` instead.
* **Focus order:** off-artboard buttons (Share and Replay before the summary; Continue and Pause on it) stay in the Tab
  order. Pressing Enter on them still performs the right action, but focus can land on an invisible control.
  Button `SemanticData` labels are bound to the localised label strings. The Pause button's accessible label stays
  `pauseLabel` while paused.
* **Summary grid:** when individual stats are hidden on the summary, their slots stay empty instead of re-flowing.
* **Not verified:** RTL was not verified, as no RTL locale is in scope. Haptics and sound are not used.
* **Frame rate:** there is no on-device frame-rate measurement, only the headless CPU bench above.
* **Editor open:** the `.rev` has not been opened in the Rive Editor, because it could not be exported without a login.
