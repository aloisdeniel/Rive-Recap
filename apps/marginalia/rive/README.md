# Marginalia — 2026 reading-journal recap (Rive)

A ten-scene, Wrapped-style recap for the fictional reading journal **Marginalia**,
authored as editable RML + four Luau scripts and three WGSL shaders, compiled with
the Rive CLI (1.6.0).
All user-dependent values come from a single `UserRecap` view-model instance;
the fixture data is fictional (January 1–December 31, 2026) and is not measured
activity.

```
apps/marginalia/rive/
  rive.yaml                 project (main artboard: Recap)
  rml/recap.rml             the whole document (generated, but plain editable RML)
  scripts/responsive.luau   the responsive layout rules (module): orientation, chrome, page frames
  scripts/responsive_test.luau  `rive . --test` checks for those rules across ~400 sizes
  scripts/resize_harness.luau   test fixture: resizes a hosted Recap mid-run (Resize Harness artboard)
  scripts/director.luau     sequencing / formatting / input "director"
  scripts/pagestage.luau    hosts the pages, places their frames for the real size, draws every page turn as a 3D paper curl
  scripts/paper.luau        laid-paper grain multiplied over the whole recap
  scripts/moon.luau         the engraved moon (a lit sphere, ScriptedDrawable)
  scripts/etch3d.luau       module: shared GPU plumbing for the 3D objects (patches, camera, canvases, leaf compositing)
  scripts/book3d.luau       the 3D open book (scenes 3, 4, 8, 9)
  scripts/theatre3d.luau    the 3D paper theatre (scene 5)
  scripts/lamp3d.luau       the 3D reading lamp, its light and the five volumes (scene 7)
  shaders/pageturn.wgsl     leaf curl, lighting, show-through, marbled endpaper, shadows
  shaders/paper.wgsl        procedural paper (fibres, laid/chain lines, specks, edge wear)
  shaders/moon.wgsl         sphere shaded as a copperplate engraving
  shaders/etch3d.wgsl       parametric-patch 3D (books, arches, curtains, lamp) printed with engraved hatching; the lamp's light pass
  shaders/leafcomp.wgsl     composites a page's 3D objects onto its turning leaf
  tools/build_rml.py        generator for rml/recap.rml (+ art.py, rmlkit.py)
  tools/capture.py          headless capture helper (taps, fixtures, viewports)
  tools/capture_all.sh      regenerates captures/
  tools/capture_responsive.py  the responsive matrix -> captures/responsive/ contact sheets
  tools/motion_preview.py   renders captures/motion-preview.mp4
  tools/probe.sh            prints key UserRecap values after a scripted run
  fixtures/                 sample.json, zero.json, extreme.json
  assets/fonts/             Cormorant Garamond (+ Italic), Libre Franklin, OFL texts
  captures/                 stills and transition frames (walkthrough: ../video.webm)
  build/marginalia-recap.riv
```

`rml/recap.rml` is generated by `python3 tools/build_rml.py` (stdlib only; the
Rive CLI also writes ids back into it on build, as it does for any RML). The
generator exists because ten scenes × seven timelines and the scene/ribbon
transition graphs are mechanical; the output is ordinary RML that opens and
edits like any other. If you hand-edit the RML, stop regenerating (or port the
edit into `tools/art.py`).

## Improvement pass (October 2026)

The first version worked but read as "solid": a page turn that was a 2D
`scaleX` squash (type visibly compressed mid-turn), flat parchment, a ribbon
that hung across the header's year and over copy, and a few weak scenes. This
pass keeps the contract, events, fixtures and behaviour checks intact and
raises the craft.

**What changed**

| Area | Before | After |
|---|---|---|
| Signature page turn | 2D fold (`scaleX` about the spine + travelling shade) | a real **3D paper curl on the GPU**: the leaving page lifts from its lower-right corner (anticipation: a small lift and settle), rolls over a moving cylinder whose radius swells mid-turn, and leaves past the spine. Lit relative to the flat page (which stays pixel-exact), warm sepia shadows, a sheen along the crest, the **back of the leaf shows the print faintly through the paper, mirrored**, the hovering flipped part shadows the flat page and the roll casts a soft shadow onto the next page. 4x MSAA. Back navigation un-rolls the earlier page back over (live-textured: its content keeps playing as it lands, the corner settles last). Reversing mid-turn retargets the leaf; rapid taps stack up to two leaves |
| Opening | intro page fades in | the recap **opens on a closed cloth book** (oxblood, gilt frame, stamped wordmark + bound year). After a beat the board cover swings open (a stiffer, slower leaf) showing a procedurally **marbled endpaper** on its back, revealing the pop-up city as it rises |
| Paper | flat fills | a laid-paper texture generated once on the GPU (fibres, laid and chain lines, pulp specks, a worn warm edge), multiplied over the whole recap so pages, type and chrome share one stock |
| Moon (scenes 4 -> 5) | flat disc with three crater ellipses | an **engraved sphere**: lit, with seas and craters, printed as latitude hatching that swells with darkness, cross-hatching in the deepest shadow, stipple in the seas, gilt outline; slow libration (static under reduced motion / pause). Still the carried object: keyed swing, carry and spotlight shrink apply |
| Bookmark ribbon | hung from the screen top, crossed "2026" (6, 10) and copy (3) | emerges from under the progress rule (the book's headband); every pose re-placed clear of copy and header; drawn *above* the turning leaf, so it stays unbroken through every cut |
| Scene 3 (pages) | thin noodle strokes, clipped book, support line colliding with it | a gilt-edged band of page edges (body, hairlines, dark fore-edge, gilt edge, shadow) streams out of an open book, sweeps across the page and runs in behind the numeral's last digit; loose leaves lift off toward the number as it resolves |
| Scene 6 (passages) | small slips, large dead area | larger slips with shadows piled under the widened bookmark, ornaments balanced round it |
| Scene 7 (streak) | radial "stain" glow | a brass reading lamp swings in, its bulb lights and a cone of light falls on a five-volume stack whose day tabs tick out |
| Scene 8 (book club) | wire-like strokes | satin ribbons (selvedge, body, sheen line) weaving round the book; two answering quote marks |
| Scene 10 (summary) | headline broke as "A little year. A / lot of you." | one line where it fits, two balanced lines (fitted) for longer copy |
| Replay icon | arrowhead sat on the arc's start, pointing nowhere | rebuilt from geometry: clockwise arc open at the top, arrowhead on the arc's end aligned to its tangent |

**Architecture change (why).** Headless capture (`--screenshot`, which the
video renderer uses) runs `advance` every frame but `draw` only for the final
frame, so a "snapshot the old page in draw" approach cannot work there (and is
fragile on hosts that skip draws). The former single `Scenes` artboard is
therefore split into **ten `Page N` artboards**, plus **`Carry`** (ribbon +
moon) and **`Cover`**. `scripts/pagestage.luau` (a `ScriptedLayout` in the
stage, replacing the `NestedArtboardLeaf`) hosts them as instances bound to the
same `UserRecap` instance and keeps a tiny book model: a flat base page plus
leaves in flight, each easing toward turned (1) or landed (0). Each leaf is the
page's live artboard rendered into a canvas every frame and curled on the GPU.
The pages' own state machines now keep a leaving page fully drawn for 1.2 s
(longer than any turn) instead of folding it themselves. All choreography,
idle loops, persona layers and the summary layers are unchanged and live in
their page's state machine.

**3D / shader techniques used.** Scripted GPU rendering (Luau `GPUCanvas`,
`GPUPipeline`, WGSL): a 61x103 grid leaf deformed in the vertex shader
(cylinder curl, pinhole perspective, perspective-correct varyings), a depth
buffer, per-pixel curl angle in the fragment shader (no faceting along the
fold), two pipelines sharing one explicit bind-group layout (cast-shadow pass,
leaf pass), 4x MSAA resolved into the canvas. Fragment-only shaders for the
paper texture (rendered once per resize) and the engraved moon (re-rendered
only when its turn moved visibly, only on scenes 4-5). No `discard` anywhere,
no per-frame buffer allocation, views created once per resize (see `rive docs
gpu-performance`). Not used: imported 3D meshes / bones (nothing in the brief
needs them), a 3D book object (the curl already carries the "real book" read
without competing with the pages' art).

**Fallbacks.** No shader support -> the leaf folds flat toward the spine (2D,
same book model), the paper overlay is skipped, the moon draws as a flat
vector disc. Reduced motion -> no cover, no turns, no libration: the pages'
own 200 ms cross-fades, final values at once (unchanged behaviour).

**New compromises.**
- The leaf's front is the page rendered into a canvas at the presenting pixel
  density (`resize` scale) - sharp on device; headless captures are @1x.
- Carried objects (ribbon, moon) float *above* the turning leaf by design;
  the moon swinging in for scene 4 crosses the leaving page 3.
- The cover hides part of the intro entrance (towers rising) for its first
  ~1 s; the wordmark banner reveal still plays after it opens.
- Three or more navigations inside one turn (0.84 s) complete the oldest leaf
  at once (two leaves in flight is the cap).
- `scripts/` are unsigned in local builds: web hosts need a signed
  `rive ... --publish` build (not done here) for any of the scripted effects.

**Performance** (same machine and method as below; CPU-side CLI figures, not
device GPU time): `.riv` 2.32 MB -> **2.48 MB** (+160 KB: three scripts, three
shaders, the cover). `--bench=600` (intro): advance mean 0.024 -> **~0.02 ms**,
render-record mean 0.104 -> **~0.095 ms** (p95 0.15 ms). `--bench=1200` with
`autoAdvanceSeconds=3` (two page turns inside the run): render mean ~0.095 ms,
p95 0.15 ms, max 0.74 ms; no wasm memory growth. GPU cost per turn frame: one
page render into a canvas + one MSAA pass of ~6.2k vertices; idle frames draw
one page + the cached paper image.

## Fix pass (user feedback, October 22 2026)

Feedback: the scene 3 "path" looked crude; scene 5 should be 3D; the scene 7
lamp was too simple; the scene 8 ribbons clipped and ended in sharp cuts; the
books in scenes 8 and 9 looked flat.

| Scene | Before | After |
|---|---|---|
| 3 | the page-edge band was a stack of 30-unit strokes cut square at both ends | every line of the band (paper body, 12 leaf hairlines, ink fore-edge, gilt edge, shadow) is offset from a resampled spine by a **taper**, so the band leaves the book's gutter narrow, swells, and converges to a point behind the numeral. The body stops short of the tips so the fine lines alone draw them (etched ends); the hairlines end at slightly different lengths. Still trimmed strokes, so it still streams out of the book |
| 5 | flat theatre | a **3D stage** (`theatre3d.luau`): boards and two risers in perspective, night backdrop with engraved stars, velvet curtains with real folds that part and tie back, pelmet with a gilt rail, nine arches standing in three rows that **unfold up from the boards** (hinged, back row first). The carried moon is a real **spot light**: it pools on the stage and lights the arches. Arch k is lit only when `genresExplored >= k`; unexplored arches stay engraved ghosts |
| 7 | 2D brass arm, gradient cone | a **3D architect's lamp** (weighted foot, two arms, ball joints, brass cone shade lit warm inside, glowing bulb). The bulb is a spot light on **five 3D volumes** (cloth covers, boards, page blocks, rounded spines with gilt bands) that drop in as before. A second GPU pass draws the light: a golden cone with soft falloff, a pool on the top volume, **dust motes** drifting in the beam, and a slight dimming of the page around the lamp that fades out before the canvas edge. The day tabs stay vector |
| 8 | ribbons ran off the canvas (portrait, tall landscape) and ended in butt cuts | every ribbon point is inside the illustration box (x within +-175, y >= -242) at every size; both ends of each ribbon are **swallowtails** (body, selvedge and sheen continue into the notch). The ribbons now hang over the book's tail like bookmarks; the quotes sit inside the V |
| 8, 9 (and 3, 4) | flat open book | a **3D open book** (`book3d.luau`): cloth boards with thickness and overhang, page blocks whose tops rise out of the gutter and roll to the fore-edge, greeked type, leaves as fine lines on the tail and fore-edge, a soft contact shadow, engraved hatching in the shade. It opens (both halves stand up and fall open) on each scene's old timing. Used for every open book outside the intro so they match |

**How (3D).** One shader, `etch3d.wgsl`: every object is a list of up to 96
parametric *patches* (quad, frustum, sphere, page block, arch ring/walls/door,
curtain, face) held in one uniform array. The vertex shader evaluates the
surface from (vertex index -> grid cell, instance attribute -> patch), takes
normals by central differences, and projects through a pinhole camera; one
instanced draw, depth buffer, 4x MSAA. Fragment: key + spot + specular, then
the moon's engraving technique (object-space hatching that swells with
darkness, cross-hatching in deep shade). Materials: page type, page edges,
cloth, brass, velvet, boards, night sky, soft shadow catchers. No `discard`.
No coplanar faces: shadow catchers sit 0.35-0.6 units above what they lie
on, recessed page faces 2 units behind the boards, overlapping rings 0.5-1
unit apart.

**Rules kept.** Each drawable re-renders only while its pose or size changes
(the lamp's light pass runs per frame only while the motes drift). Canvases
are sized to the object's box at device resolution: the Page Stage publishes
the device scale (`_devScale`, a new private VM number) and each object
multiplies it by its page's art-frame scale from `responsive.luau`, capped
at 4.2 MP. Reduced motion: settled at once, motes still. Pause
(`_motionPaused`): frozen. Back navigation: settled. No shader support: the
objects draw nothing and the Page Stage leaves the old vector versions
(wrapped as `Flat Fallback N`) visible, still animated.

**Turning leaves.** A page that turns is drawn into a 2D canvas, and a 2D
canvas cannot show an image the GPU produced in the same frame (checked: the
objects vanished from every leaf in headless captures, which is how the
video is made). So the Page Stage renders such a page with its objects drawing
nothing, renders a half-resolution key where they paint pure magenta, and
composites each object's texture into the leaf through that key
(`leafcomp.wgsl`). The page's layering survives (ribbons over the book, the
door over the book, the light cone over the stage), and the objects curl with
the paper.

**Checks.** `rive . --test` 11/11 (no check changed), `--verify` and
`inspect --summary` clean, the README probes give the same results (95 s
auto-advance -> 10, `screenChanged` x9, `recapFinished` x1; 5 taps -> 6;
hidden 2/3 -> 8 segments; backgrounded freezes; zero fixture). Verified at
320x568, 390x844, 430x932, 820x1180, 1024x768 and 1280x720, settled and
mid-turn, forward and back, reduced motion, pause mid-entrance, the extreme
fixture, personas 0 and 2 (`captures/fixes/`: before/after crops and
six-size sheets).

**Cost.** `.riv` 2,524,261 -> 2,778,421 bytes (+254 KB: four scripts, two
shaders, the vector fallbacks kept, the denser scene 3 band). `--bench=600`
on scene 7 (light pass every frame): render mean 0.24 ms, p95 0.25 ms, no
wasm memory growth; intro 0.16 ms in the same run (CLI, CPU-side, measured
while video renders were running, so not comparable to the figures below).

**Compromises.** The key mask is half resolution, so on a leaf an object's
edge against something drawn over it is a little soft. During a turn the
Page Stage renders a page with 3D objects twice. The lamp's dimming is a 2D
overlay, so it also tones the parchment and the day tabs near the lamp.
The day tabs stand a few units off the right ends of the upper volumes, as
they did in the vector stack.

## Responsive layout

The recap adapts to any canvas. There are two layouts, chosen by width only:

| Artboard width | Layout | Chrome | Pages |
|---|---|---|---|
| **< `layoutBreakpoint`** (default 768) | **portrait** | header across the top, controls centred across the bottom | copy on top, illustration below, standing on the floor of the stage |
| **≥ `layoutBreakpoint`** | **landscape** | header across the top, controls together at the bottom right | an open **spread**: the copy column on one page, the illustration on the facing page, the bookmark ribbon lying in the gutter |

Because the rule is width only, a tall 768×1024 or 820×1180 canvas is
landscape and a short 667×375 or 740×360 is portrait. Each layout then
follows the real size continuously; nothing is letterboxed.

**`layoutBreakpoint`** (number, default `768`, host-owned) is a **contract
addition** on `UserRecap`. The file compares the artboard's real width to it
every frame, so the host can retune it at any time; a non-finite or
non-positive value falls back to 768. The current orientation is published as
the private `_landscape` (bool), recomputed whenever the canvas is resized,
including across the threshold in the middle of a scene: the scene, its
progress, its state and the events are untouched (no `screenChanged`), any
page turn in flight lands where it was going, and the new layout is in place
on the next frame.

### Mechanism

* **One rule module**, `scripts/responsive.luau` (a Luau module, pure
  functions): from the real artboard size and the breakpoint it returns the
  chrome metrics and, for each page, one transform per frame. It is used by
  both scripts and tested by `scripts/responsive_test.luau`.
* **Chrome**: the Director (`scripts/director.luau`) reads its own size (the
  root artboard, resized by the host's layout fit) and writes `_landscape`,
  `_vw`, `_vh`, `_headerH`, `_headerPadT`, `_controlsH`, `_controlsPadB`,
  `_marginX`, `_controlsAlign`. The header and controls are absolute
  `LayoutComponent`s whose height, padding and alignment are **bound** to
  those numbers, so the engine reflows them (the primary button grows with
  the row up to 340). Heights compact smoothly on short canvases (header
  76 → 44, controls 104 → 58); controls stay 48×48 and 54 tall. The progress
  segments, the tap zones (left third back, right two-thirds next, above the
  controls band), hold-to-pause and the parallax band all use the real size.
* **Pages**: every page is now the **whole canvas** (the header and
  controls draw over it), so the paper bleeds edge to edge and every page turn
  covers the full viewport. Each page's art is still authored in the
  390-unit design space of the portrait master, grouped into named frames that
  are never keyed: `Copy Frame`, `Art Frame`, `Bleed Front`/`Bleed Back`
  (bands that run edge to edge: the hills of scene 1, the bridge and the water
  of scene 2), `Foot Frame` (scene 3's caption), `Wide Frame` and `Sky Frame`
  (scene 10), `Empty Frame` (the zero-user summary), `Paper Frame`. The Page
  Stage (`scripts/pagestage.luau`) moves and scales them through
  `Artboard:node(name)` whenever the size or the breakpoint changes. All
  choreography stays inside the frames, untouched.
* **Arrangements** (all computed, all continuous):
  * portrait *column*: copy at the top (scale `width/390`, 0.733–1.3),
    illustration below, scaled to the space left and anchored to the floor;
    *unit* for scene 3 while it fits, so the page-edge ribbon still runs into
    the numeral; a short portrait stage (wider than 1.25× its height) puts the
    illustration beside the copy (*row*);
  * landscape *row*: the spread. Scenes 3 and 9 mirror it (illustration on
    the left page); scene 3's rule and support become a caption under the
    illustration; in a **tall** landscape frame (768×1024, 820×1180) the
    spread *staggers*: the copy column opens the page at the top, the
    illustration takes the lower part on the other side;
  * scene 10 has its own landscape arrangement: a new **wide summary card**
    (720×220, bookplate beside the five stats in a row, with its own assembly
    and persona/name layers) beside or under the headline, or the tall card,
    whichever keeps the card largest; the skyline stands on the floor;
  * the persona reveal: plate on the left page, name and description on the
    right.
* **Carried objects**: the ribbon's horizontal place is no longer keyed; the
  Page Stage glides the Carry's `Ribbon Frame` with the pose morph (760 ms):
  the page margin in portrait, the gutter of the spread in landscape, over the
  slips (6) and the card's corner (10). Its length is clamped above the
  controls. The `Moon Frame` takes the illustration transform of scenes 4–5
  and is eased with the 4 → 5 carry.
* **Cover**: the closed book fills the canvas; its gilt rules are bound to
  `_vw/_vh`, the fleurons and the stamped title are placed by script. The
  header and controls fade in as it opens (`_chromeAlpha`); the bookmark lies
  under the cover.
* **GPU surfaces**: the leaf canvases and the GPU canvas are sized to the
  real page at device resolution (`resize` scale), capped at ~4.2 MP per leaf
  on very large canvases; the leaf mesh keeps ~6,100 square cells whatever the
  aspect; the roll radius follows the page's shorter side, so a wide page
  bends like a phone page. The paper grain renders at device resolution
  (capped at 8 MP); the engraved moon renders at 6 px per point so it stays
  sharp at spread scale.
* **Readable minimum**: 11 pt. Every copy font is at least 15 design units
  and copy frames never scale below 0.733; the summary card's unit labels are
  14.5 and the card never scales below 0.759 (the 390×844 look changed a
  little for this: units and support lines 14 → 15, card labels 10.5 → 14.5).

### Host setup

Use the runtime's **layout fit**, so the `Recap` artboard is resized to the
canvas (and resized again on every window resize or rotation) instead of being
scaled: web `new Layout({ fit: Fit.Layout })` and call
`rive.resizeDrawingSurfaceToCanvas()` on resize (React: the same `Layout` in
`useRive`), Apple `fit: .layout`, Android `Fit.LAYOUT`, Flutter `Fit.layout`.
These names are from the runtimes' current APIs; check them against the
version you ship. Bind the same `UserRecap` instance as before; optionally
write `layoutBreakpoint`. The CLI's default `--fit=layout` does the same:
`rive apps/marginalia/rive --viewport=1280x720`.

### Sizes tested

Every scene settled, plus a mid-turn frame (4 → 5 at 330 ms), at the
validation matrix — portrait 320×568, 360×640, 390×844, 430×932, 600×960,
767×1024, 667×375, 740×360; landscape 768×1024, 820×1180, 1024×768, 1280×720,
1440×900, 1920×1080, 2560×1080, 1366×600 — in `captures/responsive/`
(`tools/capture_responsive.py`: one contact sheet per scene, portrait row
above, landscape row below). The rule module is also checked on a grid of
~400 sizes from 320×360 to 2560×1440 (`rive . --test`). Supported range:
any width; heights from 360; a canvas narrower than 560 needs at least 560 of
height (a phone held upright). 390×844 is the portrait master: its frames are
the identity, so it renders as before (bar the larger small type).

The **Resize Harness** artboard (and `scripts/resize_harness.luau`) is a test
fixture shipped in the `.riv`, never shown by default: it hosts `Recap` and
changes its size mid-run, which the CLI's `--viewport` cannot. Hosting it
showed that the Page Stage's `init` can run again with the instance the host
finally binds; the Page Stage now rebinds to it (before, a re-init was
ignored).

### Compromises

* Each page is one composition in a 390-unit design space placed as blocks
  (copy, art, bands), not a free reflow of every element: text boxes keep
  their authored widths, so a copy column scales rather than rewraps.
* Bands are stretched horizontally (and down to the floor in a centred
  spread); they lost their near-layer parallax.
* The tall landscape frames (768×1024, 820×1180) are the weakest: a spread in
  a portrait-shaped frame; the stagger uses the height but leaves more
  parchment than a phone layout would.
* On the smallest phone (320×568) the illustrations get what the readable
  copy leaves: scene 3's page-edge ribbon in particular is small.
* Short portraits (667×375, 740×360) run at the type floor (11 pt) with
  compact chrome; scene 3's caption moves under its illustration there.
* The header and controls are hidden for the first ~0.6 s while the closed
  cover fills the screen (they fade in as it opens, fully by ~1.1 s; reduced motion skips the
  cover). They are still focusable and hit-testable.
* The leaf texture is capped at ~4.2 MP, so a 2560-wide @2x page turns at a
  little under device resolution for its 0.84 s.

## Architecture

| Artboard | Size | Role |
|---|---|---|
| `Recap` (main) | authored 390×844; resized to the canvas by the host's layout fit | chrome: header (wordmark, year, progress), controls (heights / padding / alignment bound to the layout properties), the full-canvas stage; the `Director` script; the `Page Stage` script (stage); the `Paper Grain` overlay; events; keyboard/focus; bound to `UserRecap` |
| `Page 1` … `Page 10` (components) | 390×664 design space; drawn as the whole canvas | one scene each, with its own state machine (scene layer, plus Persona for 9 and the summary/card layers for 10). Hosted as script instances by `Page Stage`, which places their frames for the real size (see Responsive layout) |
| `Carry` (component) | 390×664 design space | the objects carried through the cuts: the bookmark ribbon (10 poses; placed by `Ribbon Frame`) and the moon (swing, carry, spotlight; `Moon Frame`). Drawn above the pages and the turning leaf |
| `Cover` (component) | fills the canvas | the closed book the recap opens on (static artwork, a one-state machine so its binds apply) |
| `Resize Harness` | 1280×720 | test fixture only: hosts `Recap` and resizes it mid-run |
| `ShareCard` (component) | 340×460 | the static, chrome-free share card for the host to snapshot |

Draw hierarchy per page: `Scene N` › `Content` (`Copy` — never parallaxed —
then `Parallax … (near/mid/far)` groups), `Paper`. The stage draws, bottom to
top: the base page, any leaves in flight (a lower page number on top), then
`Carry`. Forward navigation turns the current page away to reveal the next one
already playing underneath; back navigation lands the earlier page back over.

### State machines

**Page N** (one per page)
- `Scene N`: `Hidden → Enter | Enter Back | Static(reduced motion) → Idle → Exit | Exit Back → Hidden`, driven only by `currentScreen`, `_navDir` and `reducedMotion`. `Exit`/`Exit Back` hold the page fully drawn for 1.2 s (the Page Stage script turns or covers it), `Enter Back` arrives settled. Rapid navigation is safe: every page independently resolves to "am I current / before / after", and a page re-requested mid-exit goes straight back in.
- Page 9 adds `Persona`: per-persona `Reveal → Idle`, `Static`, `Leaving` states, keyed on `_personaRow`; a persona change mid-scene clears to `Hidden` before the new reveal, so two personas never mix.
- Page 10 adds `Summary Mode` (full card vs zero-user invitation), `Summary Card Persona Mini`, `Summary Card Reader Name`.

**Carry**
- `Ribbon`: one pose per scene; 10×9 transitions (760 ms ease-in-out, 0 ms under reduced motion). The ribbon's 13 path vertices are keyed per pose, so it *deforms* between scenes rather than sliding.
- `Ribbon Flutter`: restrained idle sway (off under reduced motion).
- `Moon Carrier`: the moon swings in on its pendulum in scene 4 and is **carried** (820 ms) into scene 5 where it shrinks into the theatre spotlight; reversible.

**Page turns** are not a state machine: `scripts/pagestage.luau` watches
`currentScreen`/`_navDir`/`reducedMotion`/`_motionPaused` and animates leaves
(840 ms; cover 1.1 s after a 0.45 s hold). Paused freezes leaves and stops
advancing every hosted artboard (the former `NestedArtboardLeaf.isPaused`
binding).

**Recap** (root, 8 layers + listeners): three event layers, controls mode
(Continue/Pause ↔ Share/Replay), pause/play icon, three focus-ring layers;
listeners for the three buttons (click + screen-reader tap + Enter), focus/blur,
←/→/Space/Tab/Shift+Tab, and three diagnostic event counters.

**ShareCard**: persona mini-emblem + optional reader-name layers.

### The Director script (`scripts/director.luau`)

A `ScriptedLayout` filling the root artboard. It is the in-file host adapter
and the sequencer "brain"; it never draws scene art (it draws only the
progress segments). Each frame it:

1. builds the eligible list from `showScreen1..10` (1 and 10 always eligible; 9 only when at least one stat is eligible) and validates `currentScreen`;
2. applies queued commands (`_cmd*` triggers from buttons/keys, and its own tap/hold recognition) — navigation writes `_navDir`, then `currentScreen`, and fires `_evtScreen` (the Page Stage script sees the change and turns the page);
3. computes pause = `isPaused || hold || isSharing || isBackgrounded` → `_motionPaused` (freezes every hosted artboard, the page turn and the timer);
4. runs the dwell timer *after* the entrance settles (1.8 s; 0.25 s reduced) with `autoAdvanceSeconds` clamped to 3–120 s, writes `screenProgress`, auto-advances, and on the summary fires `_evtFinished` once (latched until Replay);
5. formats every stat into its `*Text` string (locale separators), counting the current scene's hero value from 0 over 200–1200 ms (ease-out cubic) on forward entry only;
6. maps `personaIndex` → `_personaRow` (unknown → 0), `personaName`, `personaDescription`, `personaColor`, all in the same frame;
7. composes `a11yAnnouncement`, `visibleScreenCount`, `visibleScreenIndex`;
8. eases pointer parallax into `_parallaxX/_parallaxY` (stage band only; zero under reduced motion; frozen while paused).

## Binding & event contract

One view model, **`UserRecap`**, one instance, bound to `Recap`; the Page Stage
script instantiates `Page 1…10`, `Carry` and `Cover` with that same instance. The host binds the **same instance** to
`ShareCard` when it snapshots. No scene owns a copy of any statistic.

**Why not Rive's `viewModelType="global"`?** Tested with this CLI: an artboard
bound to a global view model gets a *separate* instance from the global one
(`--data-dump` showed two diverging copies), and `--data` cannot reach globals.
That would violate "one shared instance", so `UserRecap` is a normal view model
that is global to the experience by construction (every artboard binds the one
instance).

## Measurements (Apple M5 Pro, macOS 26.6, Rive CLI 1.6.0, headless @1x)

- `.riv`: **2.52 MB** (2,524,261 bytes), of which 2.10 MB are the three embedded variable fonts. Responsive pass: +44 KB (+1.8 %) over 2,480,036 bytes (the layout module, the wide summary card, frames, the resize harness). Before the improvement pass: 2.32 MB.
- `rive --bench=600` (intro scene, all scripts as published): advance mean ≈0.02 ms (p95 0.04–0.07), render-record mean ≈0.095 ms (p95 0.15, max 0.4–0.7 ms); `--bench=1200 --data=autoAdvanceSeconds=3` (includes two page turns) is the same within noise; no wasm memory growth. These are CPU-side figures from the CLI, not device GPU frame times; no physical phone was available, so device frame-rate is **not measured**.
- Per page-turn frame on the GPU: one page re-rendered into a canvas, one 4x MSAA pass (shadow quad + 6.2k-vertex leaf). Idle frames: one page + `Carry` + one cached paper image (multiply).
- Object counts: pages 1.0k–2.4k objects each (Page 9 largest), Carry ≈3.2k (mostly the 10×9 ribbon transitions), Cover ≈100, Recap ≈480.
- Budget choices: no particles, no per-count objects (7 tabs, 9 arches, 13 slips regardless of value), 4 clip masks total, hidden pages sit in 1-frame states and are not drawn, GPU work only while something is on screen (leaves in flight, moon on 4–5), the paper texture is generated once per resize.

## Unsupported techniques & substitutions

- **Sequencing in a script, visuals in state machines.** Skipping hidden scenes, the dwell timer, hold-vs-tap and locale formatting are not expressible cleanly in state-machine conditions; the Director script decides *which* scene, and the state machines own *every* visual state, transition and event. The sequencing state machine is therefore the pages' state machines + the Director, not a single pure state machine.
- **Lines of type flowing into paths** — `TextFollowPathModifier` is not used (all real text is bound model copy that must stay readable); substituted by nine page-edge strokes drawn along a path with keyed `TrimPath`s (scene 3) and ribbons drawn with trims (scenes 8, 9).
- **3D page turn** — Rive transforms have no perspective, so the turn is rendered by script on the GPU (`GPUCanvas` + WGSL) from the page's live artboard; a 2D fold remains as the no-shader fallback.
- **Raster paper grain** — no bitmap is shipped; the grain is generated procedurally on the GPU at load (and skipped where shaders are unavailable, leaving the vector parchment).
- **Count-up** — Rive has no number tween for bound text; the Director writes the intermediate formatted strings.
- **Locale formatting / pluralization** — no ICU in the runtime; grouping separators are a small table in the Director, pluralization is the host's job.
- **Event payload** — the `screen` custom property on `screenChanged` is bound to `currentScreen`; runtimes that do not report event properties must read `currentScreen`.
- **Focus ring** — Rive has no `:focus-visible`; focus/blur listeners write `_focus`, which drives an oxblood ring. The Continue control is focused at start, so the ring shows even for touch users.

## Limitations (honest)

- **`.rev` was not produced**: `rive . --once --rev=build/marginalia-recap.rev` stops with `Not logged in. Run: rive login`. After `rive login`, run that command to write `build/marginalia-recap.rev` (the `.riv` builds without a login).
- Navigating while paused resumes playback (the scene state machine is frozen while paused, so a change would otherwise be invisible).
- Responsive compromises are listed under Responsive layout (tall landscape frames are the weakest).
- The Director's persona table holds English defaults; a host that localizes must write `personaName`/`personaDescription` itself (they are preserved, but a stale localized string is not detected if the host changes the index without updating the text).
- RTL was not verified (no RTL target locale in the brief); layouts are authored LTR.
- Device frame-rate/thermal measurements were not possible (no device attached); only CLI bench figures are recorded.
- The page curl is a cylinder model (a corner peel past the spine), not a cloth simulation; the board cover uses the same model with a large radius.
- Scripted effects need a GPU-capable runtime and a signed `--publish` build on the web; elsewhere the vector fallbacks apply.
- Fonts are full variable families (2.1 MB). Subsetting would cut the file ~80 % but produces Modified Versions under the OFL (reserved-name rules), so it was not done.
